# T-Dash 手动验证清单

本文档用于本地工具链安装后的人手验证。当前项目以 Flutter 手机仪表盘 App 为主，PWA 原型作为参考验证面。

## 2. 仍需人工确认的工具步骤

### 2.1 接受 Android SDK License 并安装 SDK 包

Android SDK 的 license 需要由开发者本人确认。进入仓库根目录后执行：

```bash
cd "/mnt/c/Users/ASUS/Documents/NewProject"
```

先接受 license：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u NO_PROXY \
  HOME=/tmp/tdash-home \
  JAVA_HOME="$PWD/.toolchains/jdk" \
  JAVA_TOOL_OPTIONS=-Duser.home=/tmp/tdash-home \
  PATH="$PWD/.toolchains/jdk/bin:$PATH" \
  "$PWD/.toolchains/android-sdk/cmdline-tools/latest/bin/sdkmanager" \
  --sdk_root="$PWD/.toolchains/android-sdk" \
  --licenses
```

看到 license 提示后，阅读并输入 `y` 接受。

然后安装 Flutter 3.41 当前需要的 Android SDK 包：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u NO_PROXY \
  HOME=/tmp/tdash-home \
  JAVA_HOME="$PWD/.toolchains/jdk" \
  JAVA_TOOL_OPTIONS=-Duser.home=/tmp/tdash-home \
  PATH="$PWD/.toolchains/jdk/bin:$PATH" \
  "$PWD/.toolchains/android-sdk/cmdline-tools/latest/bin/sdkmanager" \
  --sdk_root="$PWD/.toolchains/android-sdk" \
  "platform-tools" \
  "platforms;android-36" \
  "build-tools;36.0.0" \
  "ndk;28.2.13676358"
```

### 2.2 可选：安装 Linux 桌面工具链

当前 App 主要目标是手机端。Linux 桌面构建不是当前手机 App 验证的必需项。

如果要让 `flutter doctor` 的 Linux desktop 项也通过，需要在 WSL 里输入 sudo 密码安装系统包：

```bash
sudo apt-get update
sudo apt-get install -y clang ninja-build pkg-config libgtk-3-dev
```

当前环境中 `sudo -n apt-get update` 返回 `sudo: a password is required`，所以这一步需要人工输入密码。

## 9. M5 BLE 配对协议检查

M5 当前应满足：

- 已核对 Tesla `vehicle-command` 官方源码中的 BLE 服务 UUID、写特征、通知特征和 2 字节长度前缀分帧规则。
- 本地 P-256 私钥通过 `flutter_secure_storage` 保存，不进入 `toString()`、日志或普通本地数据库。
- 本机公钥以 65 字节 SEC1 未压缩格式保存，首字节为 `0x04`。
- AddKey 请求按 VCSEC 字段号构造：`UnsignedMessage.WhitelistOperation.addKeyToWhitelistAndAddPermissions`，再包进 `SignedMessage` 和 `ToVCSECMessage`。
- BLE 写入使用官方 UUID：
  - Service：`00000211-b2d1-43f0-9b88-960cebf8b91e`
  - ToVehicle：`00000212-b2d1-43f0-9b88-960cebf8b91e`
  - FromVehicle：`00000213-b2d1-43f0-9b88-960cebf8b91e`
- 配对页状态机覆盖：准备密钥、扫描、连接、发送 AddKey、等待车机确认、成功、失败。
- Mock 环境可以跑完整配对成功状态机。
- 响应解析已覆盖白名单成功、车机拒绝、钥匙列表满、公钥无效、等待确认超时等失败分类。

本地命令：

```bash
cd t_dash
flutter analyze
flutter test
```

手动验证：

1. 安装调试 APK。
2. 打开 App，进入左上角菜单。
3. 确认进入 `车辆配对` 页面，而不是设置占位页。
4. 点击 `扫描车辆`。
5. 如果没有真实车辆，页面应停留在真实 BLE 扫描结果或提示未发现设备。
6. 如果使用 Mock/测试环境，选择 `Tesla Model 3` 后应进入 `配对成功`。
7. 如果是真车，选择车辆后应发送 AddKey 请求，并提示在车机屏幕上确认。

真车验证注意事项：

- 车机端需要用户确认添加钥匙，必要时按车机提示放置 NFC 卡片。
- 当前仍需要真车实测确认 Tesla 对 `KEY_FORM_FACTOR_ANDROID_DEVICE` + owner role 的接受情况；如果车辆拒绝，下一步要把角色/形态参数做成可切换或按官方示例改为 `cloud_key`。
- 真车成功后还需要补车辆记录持久化、凭证失效检测和重新配对流程。

## 10. 下一步建议

完成 M5 后，进入 M6：

1. 真车跑一次 AddKey 配对，记录车机返回状态。
