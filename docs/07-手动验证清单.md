# T-Dash 手动验证清单

本文档用于本地工具链安装后的人手验证。当前项目以 Flutter 手机仪表盘 App 为主，PWA 原型作为参考验证面。

## 1. 当前本地工具状态

已准备到 `.toolchains/` 的本地工具：

- Flutter SDK：`.toolchains/flutter`
- JDK 21：`.toolchains/jdk`
- Android command-line tools：`.toolchains/android-sdk/cmdline-tools/latest`
- Chrome for Testing：`.toolchains/chrome/chrome-linux64/chrome`

`tools/check-m0.sh` 已配置为优先使用这些本地工具，并自动设置：

- `JAVA_HOME`
- `ANDROID_HOME`
- `ANDROID_SDK_ROOT`
- `CHROME_EXECUTABLE`
- Flutter / Android / Java / Chrome 的本地 PATH

## 2. 仍需人工确认的工具步骤

### 2.1 接受 Android SDK License 并安装 SDK 包

Android SDK 的 license 需要由开发者本人确认。进入仓库根目录后执行：

```bash
cd "/mnt/c/Users/ASUS/Documents/NewProject"
```

先接受 license：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u NO_PROXY \
  HOME=/tmp/tdash-home \
  JAVA_HOME="$PWD/.toolchains/jdk" \
  JAVA_TOOL_OPTIONS=-Duser.home=/tmp/tdash-home \
  PATH="$PWD/.toolchains/jdk/bin:$PATH" \
  "$PWD/.toolchains/android-sdk/cmdline-tools/latest/bin/sdkmanager" \
  --sdk_root="$PWD/.toolchains/android-sdk" \
  --licenses
```

看到 license 提示后，阅读并输入 `y` 接受。

然后安装 Flutter 3.41 当前需要的 Android SDK 包：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u NO_PROXY \
  HOME=/tmp/tdash-home \
  JAVA_HOME="$PWD/.toolchains/jdk" \
  JAVA_TOOL_OPTIONS=-Duser.home=/tmp/tdash-home \
  PATH="$PWD/.toolchains/jdk/bin:$PATH" \
  "$PWD/.toolchains/android-sdk/cmdline-tools/latest/bin/sdkmanager" \
  --sdk_root="$PWD/.toolchains/android-sdk" \
  "platform-tools" \
  "platforms;android-36" \
  "build-tools;36.0.0" \
  "ndk;28.2.13676358"
```

### 2.2 可选：安装 Linux 桌面工具链

当前 App 主要目标是手机端。Linux 桌面构建不是当前手机 App 验证的必需项。

如果要让 `flutter doctor` 的 Linux desktop 项也通过，需要在 WSL 里输入 sudo 密码安装系统包：

```bash
sudo apt-get update
sudo apt-get install -y clang ninja-build pkg-config libgtk-3-dev
```

当前环境中 `sudo -n apt-get update` 返回 `sudo: a password is required`，所以这一步需要人工输入密码。

## 4. Flutter App 手动验证

进入 Flutter 工程：

```bash
cd "/mnt/c/Users/ASUS/Documents/NewProject/t_dash"
```

运行分析和测试：

```bash
flutter analyze
flutter test
```

验证点：

- Dashboard 页面能正常渲染，无红屏、白屏或明显溢出。
- 车速圆是第一视觉中心，速度不可用时显示 `-- km/h`，不展示伪造车速。
- GPS 正常时数据源显示 `GPS`；信号弱或精度差时显示 `GPS 弱`。
- 定位不可用、权限拒绝或服务关闭时，数据源显示 `无数据`。
- BLE 未接入前车辆显示 `未连接车辆` / `未配对`，不显示假的 `BLE 已连接`。
- 电量、续航、锁车、空调和胎压状态来自 Dashboard ViewModel；数据缺失时显示未知或占位。
- 状态卡只显示当前保留模块，不应再出现已删除的充电状态卡。
- 行驶模式激活时，控制命令被拦截并给出明确反馈。
- 点击菜单按钮显示 `设置页开发中`。

## 6. Android 构建验证

完成 Android SDK license 和 SDK 包安装后执行：

```bash
cd "/mnt/c/Users/ASUS/Documents/NewProject/t_dash"
flutter build apk --debug
```

通过标准：

- 构建生成 `build/app/outputs/flutter-apk/app-debug.apk`。
- 构建过程中没有 Android SDK、license、JDK 或 Gradle 配置错误。

如果连接 Android 真机：

```bash
flutter devices
flutter run -d <device-id>
```

也可以直接安装已生成的 debug APK：

```bash
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

真机验证点：

- App 能安装并启动。
- 仪表盘在竖屏下不溢出。
- 控制按钮触摸区域可用。
- 系统字体放大后车速圆内容不溢出。
- 首次启动会请求定位权限，不请求后台定位权限。
- 选择“仅在使用中允许”后，Dashboard 能读取 GPS 速度。
- 关闭系统定位或拒绝权限后，车速显示 `--`，数据源显示 `无数据`。
- 在室内、地库或 GPS 精度较差时，数据源可降级显示 `GPS 弱`。
- 真机移动时速度会随 GPS 变化；静止后不应持续显示明显错误的高速度。
- 车速持续高于 5 km/h 约 3 秒后进入驾驶模式，控制命令被拦截。
- 车速持续低于 1 km/h 约 5 秒后退出驾驶模式，控制区恢复可用。

## 8. M3 完成度检查

M3 当前应满足：

- `main.dart` 只保留启动入口。
- App 壳位于 `lib/app/t_dash_app.dart`。
- 主题 token 位于 `lib/app/theme/t_dash_theme.dart`。
- 路由位于 `lib/app/routing/app_router.dart`。
- Domain 模型和服务接口位于 `lib/domain/`。
- Dashboard ViewModel 位于 `lib/application/dashboard/dashboard_view_model.dart`。
- Dashboard Provider 组合位于 `lib/application/dashboard/dashboard_providers.dart`。
- GPS 车速实现位于 `lib/infrastructure/gps/gps_velocity_provider.dart`。
- 定位插件网关位于 `lib/infrastructure/gps/location_gateway.dart`。
- 驾驶模式检测位于 `lib/application/vehicle/driving_mode_detector.dart`。
- Android Manifest 已声明前台定位权限。
- Widget 和单元测试覆盖 Dashboard、Provider 切换、GPS 降级和驾驶模式。
